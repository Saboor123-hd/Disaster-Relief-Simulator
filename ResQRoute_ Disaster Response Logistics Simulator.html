MST backbone (Kruskal)

MST connects the selected network nodes using a minimum-total-weight set of roads without creating cycles. It is only a backbone: delivery routes still follow road status, deadlines and priorities.

Algorithms used

  • Graph: places = nodes, roads = edges
  • Kruskal MST: backbone
  • Path enumeration + Dijkstra-style least cost: baseline and shortest route
  • Scoring rule: priority-aware route
  • Greedy: critical, then high, then deadline, then unmet demand
  • Multi-depot split allocation
  • 0/1 knapsack DP: local delivery planning
  • Seeded lognormal noise: uncertain travel times

Explain This Simulation

  1. The map is a road network after a disaster.
  2. Nodes are places (depots, hospital, camps, shelters). Edges are roads with distance, time, priority and condition.
  3. MST (Kruskal) picks the cheapest set of roads that connects everything with no cycles: a basic backbone.
  4. Greedy prioritization serves critical places first, then high, then medium, using deadlines to break ties.
  5. Multi-depot allocation: if one depot runs out of a resource, the next depot covers the rest. Stock never goes below zero.
  6. The shortest path only minimizes time. The priority-aware route can pick a slightly longer emergency corridor when the destination is urgent and the deadline is still met.
  7. The DP step chooses which deliveries fit into one vehicle's capacity with the highest urgency value.
  8. Uncertainty adds random delays to every road. Higher uncertainty means more late deliveries.
  9. Before = nearest-first, nearest-depot, shortest-path policy. After = ResQRoute. Both use the same map, stock, demand and delays, and all numbers are computed live.
